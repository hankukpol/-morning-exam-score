## 1. D-1: 자동화 알림 트리거

### 1.1 개요

현재 모든 알림은 관리자가 `/admin/notifications` 페이지에서 수동 발송.
주요 이벤트(사유서 승인/반려, 경고/탈락 판정) 발생 시 자동 발송 로직 추가.

### 1.2 신규 파일: `web/src/lib/notifications/auto-trigger.ts`

아래 함수를 구현한다.

```typescript
// web/src/lib/notifications/auto-trigger.ts

import { prisma } from '@/lib/prisma'
import { sendSolapiMessage } from '@/lib/notifications/solapi'  // 기존 발송 유틸

/**
 * 사유서 상태 변경 시 해당 수강생에게 알림 발송
 * absence_notes.status가 APPROVED 또는 REJECTED로 변경될 때 호출
 */
export async function triggerAbsenceNoteNotification(
  absenceNoteId: string,
  newStatus: 'APPROVED' | 'REJECTED',
  rejectReason?: string
): Promise<void> {
  const note = await prisma.absence_notes.findUnique({
    where: { id: absenceNoteId },
    include: { student: true, session: true },
  })
  if (!note || !note.student.notificationConsent) return

  const message =
    newStatus === 'APPROVED'
      ? `[아침모의고사] ${note.student.name}님의 사유서가 승인되었습니다.`
      : `[아침모의고사] ${note.student.name}님의 사유서가 반려되었습니다. 사유: ${rejectReason ?? '없음'}`

  await sendAndLog({
    examNumber: note.examNumber,
    phone: note.student.phone,
    message,
    type: 'ABSENCE_NOTE',
  })
}

/**
 * 주차 상태 변화(경고/탈락) 시 해당 수강생에게 알림 발송
 * weekly_status_snapshots 갱신 후 상태가 바뀐 수강생에게 호출
 */
export async function triggerStatusChangeNotification(
  examNumber: string,
  newStatus: 'WARNING_1' | 'WARNING_2' | 'DROPOUT'
): Promise<void> {
  const student = await prisma.students.findUnique({ where: { examNumber } })
  if (!student || !student.notificationConsent) return

  const statusLabel = {
    WARNING_1: '1차 경고',
    WARNING_2: '2차 경고',
    DROPOUT: '탈락',
  }[newStatus]

  const message = `[아침모의고사] ${student.name}님의 출결 상태가 [${statusLabel}]로 변경되었습니다.`

  await sendAndLog({
    examNumber,
    phone: student.phone,
    message,
    type: newStatus as any,
  })
}

// 내부 헬퍼: 발송 후 notification_logs에 기록
async function sendAndLog(params: {
  examNumber: string
  phone: string
  message: string
  type: string
}) {
  let status: 'SUCCESS' | 'FAILED' = 'SUCCESS'
  let failReason: string | undefined

  try {
    await sendSolapiMessage({ to: params.phone, text: params.message })
  } catch (e) {
    status = 'FAILED'
    failReason = e instanceof Error ? e.message : 'Unknown error'
  }

  await prisma.notification_logs.create({
    data: {
      examNumber: params.examNumber,
      type: params.type as any,
      channel: 'ALIMTALK',
      message: params.message,
      status,
      failReason,
      sentAt: new Date(),
    },
  })
}
```

## 2. D-2: 학생 셀프 조회 포털

### 2.1 개요

수강생이 **수험번호+이름**으로 로그인하여 본인 성적·출결·포인트·공지를 모바일에서 직접 조회.
관리자가 학생 계정을 일괄 생성하고, 학생은 별도 가입 없이 바로 접근.
Web Push 알림으로 공지사항을 실시간 수신.

**핵심 결정 사항**:
- 로그인: 수험번호 + 이름 조합 (비밀번호 없음)
- 계정 생성: 관리자 일괄 생성
- 인증: Supabase Auth 우회 → **커스텀 JWT 세션** (httpOnly 쿠키)
- UI: 모바일 퍼스트 PWA
- 알림: Web Push API (FCM VAPID)

> ⚠️ 보안 참고: 수험번호+이름 방식은 이름을 아는 제3자도 접근 가능. 성적 조회·사유서 제출 외 민감한 개인정보(전화번호 전체 등)는 노출하지 않도록 설계.

---

### 2.2 인증 설계 (커스텀 JWT)

Supabase Auth를 **학생 인증에는 사용하지 않음**. 별도 커스텀 JWT 발급.

#### 로그인 플로우

```
[학생 브라우저]
  POST /api/student/auth/login
  { examNumber: "2026001", name: "홍길동" }
        ↓
[서버]
  students 테이블에서 examNumber + name 일치 여부 확인
  isActive = true 인지 확인
        ↓
  일치하면: JWT 발급 (payload: { examNumber, sub: student.id, exp: 7일 })
  JWT를 httpOnly, Secure, SameSite=Strict 쿠키로 설정
        ↓
[학생 브라우저]
  쿠키 자동 저장 → /student 리다이렉트
```

#### JWT 발급/검증 구현

**환경 변수 추가**:
```
STUDENT_JWT_SECRET=<랜덤 32바이트 이상 문자열>
```

**신규 파일: `web/src/lib/auth/student-jwt.ts`**

```typescript
import { SignJWT, jwtVerify } from 'jose'  // jose 패키지 사용 (Next.js 엣지 호환)

const SECRET = new TextEncoder().encode(process.env.STUDENT_JWT_SECRET!)
const COOKIE_NAME = 'student_session'

export async function signStudentJwt(examNumber: string, studentId: string) {
  return new SignJWT({ examNumber, sub: studentId })
    .setProtectedHeader({ alg: 'HS256' })
    .setExpirationTime('7d')
    .setIssuedAt()
    .sign(SECRET)
}

export async function verifyStudentJwt(token: string) {
  const { payload } = await jwtVerify(token, SECRET)
  return payload as { examNumber: string; sub: string }
}

export { COOKIE_NAME }
```

**신규 파일: `web/src/lib/auth/require-student.ts`**

```typescript
import { cookies } from 'next/headers'
import { verifyStudentJwt, COOKIE_NAME } from './student-jwt'
import { prisma } from '@/lib/prisma'

export async function requireStudent() {
  const token = cookies().get(COOKIE_NAME)?.value
  if (!token) throw new Error('UNAUTHORIZED')

  let payload: { examNumber: string; sub: string }
  try {
    payload = await verifyStudentJwt(token)
  } catch {
    throw new Error('INVALID_TOKEN')
  }

  const student = await prisma.students.findUnique({
    where: { examNumber: payload.examNumber, isActive: true },
  })
  if (!student) throw new Error('STUDENT_NOT_FOUND')
  return student
}

// API Route에서 사용 (Request 기반)
export async function requireStudentFromRequest(request: Request) {
  const cookieHeader = request.headers.get('cookie') ?? ''
  const token = cookieHeader
    .split(';')
    .find(c => c.trim().startsWith(`${COOKIE_NAME}=`))
    ?.split('=')[1]

  if (!token) throw new Error('UNAUTHORIZED')
  const payload = await verifyStudentJwt(token)
  const student = await prisma.students.findUnique({
    where: { examNumber: payload.examNumber, isActive: true },
  })
  if (!student) throw new Error('STUDENT_NOT_FOUND')
  return student
}
```

### 2.6 신규 API: `web/src/app/api/student/`

#### `POST /api/student/auth/login`

```typescript
// 파일: web/src/app/api/student/auth/login/route.ts
export async function POST(request: Request) {
  const { examNumber, name } = await request.json()

  if (!examNumber || !name) {
    return NextResponse.json({ error: '수험번호와 이름을 입력해주세요.' }, { status: 400 })
  }

  const student = await prisma.students.findFirst({
    where: {
      examNumber: String(examNumber).trim(),
      name: String(name).trim(),
      isActive: true,
    },
  })

  if (!student) {
    // 보안: 수험번호 존재 여부 노출 금지 — 동일한 에러 메시지
    return NextResponse.json({ error: '수험번호 또는 이름이 일치하지 않습니다.' }, { status: 401 })
  }

  const token = await signStudentJwt(student.examNumber, student.id)

  const response = NextResponse.json({ success: true })
  response.cookies.set('student_session', token, {
    httpOnly: true,
    secure: process.env.NODE_ENV === 'production',
    sameSite: 'strict',
    maxAge: 60 * 60 * 24 * 7,  // 7일
    path: '/',
  })
  return response
}
```

#### 2.8.6 신규 파일: `web/src/lib/push/send-notice.ts`

```typescript
import webpush from 'web-push'

webpush.setVapidDetails(
  process.env.VAPID_SUBJECT!,
  process.env.NEXT_PUBLIC_VAPID_PUBLIC_KEY!,
  process.env.VAPID_PRIVATE_KEY!
)

/**
 * 공지사항 발행 시 구독 중인 학생 전체에게 Web Push 발송
 * notice 발행 API(/api/notices/[id]/publish)에서 호출
 */
export async function sendNoticePush(params: {
  noticeId: string
  title: string
  body: string
  targetExamType?: 'GONGCHAE' | 'GYEONGCHAE' | null  // null이면 전체
}) {
  // 대상 학생의 구독 정보 조회
  const subscriptions = await prisma.push_subscriptions.findMany({
    where: params.targetExamType
      ? { student: { examType: params.targetExamType, isActive: true } }
      : { student: { isActive: true } },
  })

  const payload = JSON.stringify({
    title: params.title,
    body: params.body,
    url: `/student/notices`,
  })

  // 병렬 발송 (실패해도 다른 구독에 영향 없도록 allSettled 사용)
  const results = await Promise.allSettled(
    subscriptions.map(sub =>
      webpush.sendNotification(
        { endpoint: sub.endpoint, keys: { p256dh: sub.p256dh, auth: sub.auth } },
        payload
      )
    )
  )

  // 만료된 구독(410 Gone) 자동 삭제
  results.forEach((result, i) => {
    if (result.status === 'rejected') {
      const err = result.reason as { statusCode?: number }
      if (err.statusCode === 410 || err.statusCode === 404) {
        prisma.push_subscriptions
          .delete({ where: { endpoint: subscriptions[i].endpoint } })
          .catch(() => {})
      }
    }
  })
}
```

## 11. 공통 주의사항

1. **DB 마이그레이션**: 0.4 절 방법으로만 실행 (prisma db push 사용 금지)
2. **Vercel Cron 인증**: 모든 Cron 핸들러에 `Authorization: Bearer CRON_SECRET` 검증 추가
3. **알림 발송 실패 처리**: try-catch로 감싸고 실패 시에도 notification_logs에 FAILED 기록, 원래 비즈니스 로직은 정상 완료
4. **fire-and-forget 패턴**: 자동 알림 트리거는 비즈니스 로직과 독립적으로 실행 (알림 실패가 사유서 승인을 막으면 안 됨)
5. **학생 API 권한**: 모든 `/api/student/*` 엔드포인트에서 `requireStudentFromRequest(request)` 호출 후 `student.examNumber`로 데이터 필터 강제 (authId 방식 아님)
6. **학생 인증은 Supabase Auth 사용 안 함**: `student_session` httpOnly 쿠키 + 커스텀 JWT(jose) 사용. `STUDENT_JWT_SECRET` 환경변수 발급 필요
7. **PWA 아이콘**: `web/public/icons/` 에 icon-192.png, icon-512.png, badge-72.png 준비 필요 (관리자 제공)
8. **VAPID 키 발급**: `npx web-push generate-vapid-keys` 실행 후 .env.local에 추가, Vercel 환경변수에도 등록
9. **Web Push iOS 제한**: iOS 16.4 이상 Safari에서 홈 화면 추가(PWA) 시에만 푸시 수신 가능 — 학생 안내 문구 필요
10. **신규 패키지**: `jose`, `next-pwa`, `web-push`, `@types/web-push` 설치 필요
